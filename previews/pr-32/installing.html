    Feature: Installing ghg

    The action installs ghg on the runner, and puts it on the PATH of the job's later steps
    (docs/BEHAVIOUR.md, "Installing").

    • Scenario: The release named is installed, and a later step runs it
    • Scenario: A version that is not one stops the action
    • Scenario: Building with a ghg older than 1.1.0 stops the action before it is downloaded
    • Scenario: Every option the ghg named is too old for is reported before it is downloaded
    • Scenario: The ghg installed is kept in the runner's tool cache

    • @rule-1
    • @rule-4
    1. When a push runs the action with:
      ghg-version1.1.0
    2. And a later step runs "ghg --version"
    3. Then the action passes
    4. And the log says "ghg 1.1.0 is installed."
    5. And the log says "ghg 1.1.0"

    • @rule-2
    1. When a push runs the action with:
      ghg-versionlatest
    2. Then the action fails with "ghg-version must be a version of ghg, such as 1.2.0."

    • @rule-2
    1. When a push runs the action with:
      ghg-version1.0.0
      buildtrue
    2. Then the action fails with "The action builds with ghg 1.1.0 or newer, not 1.0.0."
    3. And the log does not say "ghg 1.0.0 is installed."

    • @rule-2
    1. When a push runs the action with:
      ghg-version1.0.0
      buildtrue
      keep-in-output/CNAME
    2. Then the action fails with:
      The action builds with ghg 1.1.0 or newer, not 1.0.0.
      keep-in-output needs ghg 1.1.0 or newer, not 1.0.0.
    3. And the log does not say "ghg 1.0.0 is installed."

    • @rule-6
    1. When a push runs the action with:
      ghg-version1.1.0
    2. And a later step runs "test -n \"$(ls \"$RUNNER_TOOL_CACHE\"/ghg/1.1.0/*/)\" && echo ghg is in the tool cache"
    3. Then the action passes
    4. And the log says "ghg is in the tool cache"
